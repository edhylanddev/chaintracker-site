1. Scope and data source

Blockchain: Bitcoin mainnet. Data was retrieved from the Esplora API at https://mempool.space/api. Each response was preserved unaltered and identified by its SHA-256 hash (Appendix A). Integrity check at report time: 8 stored responses re-hashed, 0 problem(s).

2. Methodology

  • Transaction analysis: inputs and outputs were examined and heuristic tests applied for CoinJoin fingerprints and change-output detection.
  • Address clustering: addresses were grouped using the common-input-ownership heuristic (all inputs of a non-CoinJoin transaction are assumed to share an owner), optionally extended by change-output detection. Each grouping cites the transaction that supports it.
  • Wallet exploration: balances, history and counterparties were compiled from public blockchain data for the listed addresses (or addresses derived from an extended public key using a gap-limit scan).
  • Taint analysis: funds were followed forward from the source outputs using the stated allocation method. Tracing stopped at unspent outputs, attributed service endpoints, CoinJoins, the hop limit, or amounts below the threshold.

5. Limitations

  • Clustering and change detection are heuristics, not proof. Payjoin, shared custody, collaborative transactions and deliberate change-avoidance can produce false positives.
  • Attribution (labels) is only as reliable as its stated source; unlabeled addresses are not necessarily unaffiliated.
  • CoinJoin detection relies on known structural fingerprints; novel or small mixing transactions may not be recognised, and some ordinary batch payments may resemble them.
  • The taint allocation method materially changes the amounts attributed to each destination. Results under other methods may differ.
  • Off-chain movements (internal exchange ledgers, Lightning Network, custodial transfers) are not visible on the blockchain and cannot be traced here.
